# Directions guide

A direction is one complete visual idea for the page. Make at least 3. The user picks one, changes it, or mixes parts of several.

## Make each direction

- Write each direction as one standalone HTML file, with inline CSS and JS.
- Use the same content in each direction. Only the design changes.
- Use the real assets: the logo, the brand color, and the real media.
- Make the directions differ on a big axis, such as the composition, the mood, or the main motion. A color swap is not a new direction.
- Give each direction a short name and a one-sentence pitch.
- Make the hero complete. Make the other sections rough, but in the right order.
- Load each external library from a CDN with an exact version.

## Show each direction

- Take screenshots at 1440 × 900 and at 375 × 812 with `drive-surface`.
- When the hero moves, record a video of about 8 seconds: 2 seconds idle, then a slow scroll.
- Look at every screenshot and the frames of the video. Run [the taste check](taste.md). Fix each failure before you show the direction.
- Show the directions side by side. When the harness has a canvas or a page preview, use it. Otherwise give the paths of the screenshots and serve the files on a local port.
- Ask the user to pick, to change, or to mix.

## Explain each element

The user asks about elements that have no clear job. Examples: "what are those boxes?", "why so much empty space on the right?".

- Answer with the job of the element in one sentence.
- When you cannot state the job, remove the element.
- Give each empty area a job, such as rest for the eye around the headline, or fill it.

## When the user rejects every direction

- Find the cause first. Ask, or read the words of the user.
- "Boring", "too grid-like", or "it does not impress" means too little: go up the scale in [the taste guide](taste.md).
- "Too aggressive" or "ordinary" means too much noise: go down the scale, and raise the craft.
- "You did almost nothing" means the change is too small to see: add one living system, not more noise.
- Keep each part that the user praised. Name those parts in the next round.
- After a rejection of loud prototypes, refine the real page instead of making more prototypes.
