# Goal questions

Find the goal of the page before you design it. Skip each question that the conversation already answers.

## Questions

Ask them in this order, one at a time. Offer options when you can.

1. **Who.** Who visits the page, and from where do they arrive? Examples: a post on social media, a cold email, a search.
2. **Action.** Which single action do you want from the visitor? Examples: hire me, start a campaign, sign up.
3. **Five seconds.** What does the visitor understand and feel in the first 5 seconds?
4. **Proof.** Which real content proves the main claim? Examples: commits, clips, metrics, client work.
5. **Owner.** Does the user own the site, or is it a redesign pitch to another owner?
6. **Languages.** Which languages, and which one is the default?
7. **Base.** Light base or dark base? A light base with one vivid brand color is a frequent choice.
8. **Constraints.** Which stack, which host, and which content format? Record them for the build.

## Pitch mode

When the user does not own the site, the work is a redesign pitch. Turn on pitch mode in [the honesty rules](honesty.md). Ask these questions too:

- Which name signs the pitch?
- What does the user deliver to the owner? Examples: a live link, a short before and after video.

## Proof over styling

A visitor believes proof, not a style. A terminal font does not prove that a person writes code. Real commits, a real contribution graph, and real code prove it. Find the proof in step 4, and design the page around it.
